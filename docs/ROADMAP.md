# Roadmap Caliinda

Работаем по этапам сверху вниз. Один пункт = один коммит (или небольшая серия).
Отмечаем `[x]` по мере выполнения. Дизайн — по `docs/DESIGN.md`.

## Сейчас — приоритетные улучшения (идём по ним раньше этапов ниже)

- [x] **6.1 Шторка формы под статус-баром.** С клавиатурой развёрнутая шторка заезжала под
  статус-бар — вернули стандартные `contentWindowInsets`. Половинчатое открытие на свежей
  сборке не воспроизвелось; вернётся — разберём отдельно. (Бывший 3.6.)
- [x] **6.2 Снекбар удаления.** Окно отмены 5 с (с поправкой на настройки доступности) вместо
  10 с; текст — весёлые фразы `FunMessages`, как у остальных снекбаров.
- [x] **6.3 Редактирование повторяющихся событий — как в нормальных календарях.** Выбор
  «только это / это и следующие / все». «Только это» — настоящее исключение
  (`CONTENT_EXCEPTION_URI`), связанное с серией; у ещё не синхронизированной серии провайдер
  без `_SYNC_ID` теряет экземпляры — там по-старому EXDATE + отдельное событие. «Это и
  следующие» — серия обрезается, с экземпляра начинается новая (остаток COUNT, перенесённые
  экземпляры после разреза удаляются). Форма для исключений берёт правило головного события;
  в режиме «только это» блок повторения скрыт.
- [x] **6.4 Интерфейс повторений.** В форме — одна строка-сводка («Каждые 2 недели · пн, чт ·
  10 раз»), по тапу — шторка: интервал «− N +» и связанная группа день/неделя/месяц/год
  (подписи склоняются), круглые кнопки дней недели, окончание никогда/дата/количество.
  `INTERVAL` теперь часть `Rrule` и формы; детали события показывают ту же сводку.
- [x] **6.10 Переводы весёлых сообщений.** `FunMessages` ужаты с 92 фраз до 26 (по 2–3 на
  действие), каждая адаптирована под ru/de/es/fr/hi, а не переведена дословно. Убраны «утренние»
  фразы первого сообщения сессии, сезонные и общие ошибки (не использовались); пустое название —
  фраза без имени вместо захардкоженного «Untitled Event».
- [x] **6.5 Высота карточки проекта** — только от длительности: сигмоида по дням, нормированная
  на месяц (1 день — минимум, 31 — максимум; неделя ≈ ¼, две ≈ 70 %). Убрано уменьшение по ходу
  проекта (из-за него не начавшийся был выше идущего). Подпись многодневных — только даты (бывший 4.0).
- [x] **6.6 Настройки одним экраном** в духе Android 16: `LargeFlexibleTopAppBar`, секции
  «Оформление / Календари / Время / О приложении», строки `SegmentedListItem`. Часовой пояс —
  шторка с поиском вместо выпадающего списка. Подэкраны и их маршруты удалены.
- [x] **6.7 Свои чипы-подсказки.** Настройки → «Чипы-подсказки»: полный список (встроенные и
  свои) — подпись, полное название, рекомендуемые часы; добавление, удаление и сброс с
  «Отменить». В свои часы чип идёт первым (свои — впереди встроенных), дальше — по нажатиям.
  Нетронутые встроенные переводятся с языком. Жёсткие окна из `getTimeBonus` стали часами
  по умолчанию у встроенных.
- [x] **6.8 Live-уведомление о текущем событии.** Настройки → «Уведомления» (по умолчанию
  выкл., просит разрешение). Тихое постоянное уведомление: прогресс, обратный отсчёт до конца,
  «Следующее событие: …», если оно начинается не позже чем через 15 мин после текущего. На
  Android 16 — `ProgressStyle` с сегментами и `setRequestPromotedOngoing` (Live Update).
  Обновляется точным будильником (`USE_EXACT_ALARM`), после правок, загрузки, смены времени и
  `PROVIDER_CHANGED` календаря. Проверено на Android 13; Live Update на Android 16 — проверить
  на телефоне.
- [ ] **6.11 Чипы-шаблоны.** Чип работает без настройки, каждое поле необязательно.
  - [x] Дни недели: у чипа свои дни (Пн…Вс, как в повторении); встроенным — по смыслу (работа —
    будни, уборка — выходные, вечеринка — пт–сб). Уместные (день и часы) — вперёд, первые три —
    таблетки (форма, а не заливка: заливка читается как «выбрано»); не в свой день — в конец. Старые сохранённые списки получают
    дни по смыслу при чтении.
  - [ ] Длительность: авто (медиана трёх последних сохранений через чип) / своя / не трогать;
    выученная — пятой кнопкой рядом с быстрыми длительностями.
  - [ ] Время начала: не трогать / ближайшие полчаса / сейчас / ровно в ЧЧ:ММ.
  - [ ] Превью ряда чипов на выбранный день и час в настройках чипов.
  Правило: если время или длительность в форме уже меняли руками — чип их не трогает.
- [x] **6.12 Длинные названия в карточках.** Высота — по длительности, поэтому подстраивается
  текст (`TitleFit.kt`): строк столько, сколько влезает; не хватило — уже по оси ширины
  RobotoFlex (`CardCondensed`, умеренно: узость — сигнал «сейчас»); раскрытая карточка
  дорастает до полного названия (до +3 строк). Для событий дня и проектов.
- [x] **6.13 Кнопка эмодзи в поле названия.** Панель: «Подходит» (эмодзи, которые ставили к
  похожим названиям) и «Ваши» (из названий в календаре за год, частые и недавние первыми);
  пусто — стандартный набор. Тап вставляет эмодзи на место курсора отдельным словом; сами названия не трогаем.
- [x] **6.14 Ссылка в месте встречи.** `EventPlace`: адрес или ссылка; созвоны (Zoom, Meet,
  Teams, Телемост…) — названием сервиса с камерой, прочие ссылки — доменом; тап открывает
  ссылку. Пустое место — ссылка на созвон из описания.
- [x] **6.15 Даты многодневного события — кнопки.** Начало и конец в подробностях — отдельные
  кнопки, тап переносит на день.
- [x] **6.16 Тап по событию на виджете** открывает его день и подробности (день, обзор, отсчёт,
  стопка). Проверить на рабочем столе.
- [x] **6.17 Участники события** (только просмотр): свёрнуто — «Олег, Аня и ещё 3 · придут 3 из 6», по тапу — список с ответами; без переговорок, себя — «Вы», организатор первым.
- [ ] **6.18 Удаление и создание без снекбара**: удалённая карточка бледнеет с таймером и
  «Отменить», созданная — подсвечивается. Снекбар — только для ошибок. Сначала концепт.
- [ ] **6.19 Насыщенные цвета** (Vibrant): схемы от базового цвета (MaterialKolor), переключатель.
- [ ] **6.9 (подумать) Детали в карточке проекта.** Описание может быть длинным — варианты:
  1–2 строки с обрезкой, или только по тапу. Решить до реализации.

## Этап 1 — Баги

- [x] **1.1 DatePicker и часовой пояс.** M3 `DatePicker` работает с полуночью UTC, а код
  передаёт/читает millis через пояс пользователя: в UTC+ подсвечивается вчерашний день,
  в UTC− выбранная дата сохраняется на день раньше. Перевести на `ZoneOffset.UTC`:
  `CalendarScreen.kt` (initialSelectedDateMillis, onConfirm),
  `HandlePickerLogic.kt` (StartDate, EndDate + selectableDates, RecurrenceEnd).
  Вынести хелперы `LocalDate.toPickerMillis()` / `Long.fromPickerMillis()`.
- [x] **1.2 «Сегодня» после полуночи.** `CalendarScreen.kt` (`remember { LocalDate.now() }`),
  `ProjectEventsPage.kt` (flow проектов создаётся один раз), `CalendarViewModel`/
  `EventUiModelMapper`/`CalendarDateTitle` (`LocalDate.now()` в системном поясе).
  Сделать единый поток «сегодня» в поясе из настроек (от `TimeTicker`), пересоздавать
  зависимые flow при смене дня.
- [x] **1.3 Время по умолчанию около полуночи.** `CreateEventScreen.kt`: при `now + 1h`
  через полночь стартовая дата должна сдвигаться на следующий день.
- [x] **1.4 Пикер даты в шапке** открывается со старой датой — синхронизировать
  `datePickerState` с `currentVisibleDate` при открытии; убрать пустую строку
  `datePickerState.selectableDates`.
- [x] **1.5 «days left».** Округление вверх, «последний день» вместо 0, вынести в `plurals`.
- [x] **1.6 Локализация.** Строки в коде → ресурсы: «Syncing calendars…», «(No title)»,
  «Edit», «Cancel», «OK», «Regular events», `contentDescription` в AppBar/BottomBar/карточках.
- [x] **1.7 Мусор.** `app/release/` в `.gitignore`; удалить/доделать неиспользуемое:
  `WeekState`, пустой `ManagementScreen`/`AppMode.MANAGEMENT`, `validationError`/
  `generalError` в форме, дублирующий `requestEventDetails` в `EventManagementViewModel`.
