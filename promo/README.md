# Промо-ролики Caliinda

Ролики на [Remotion](https://www.remotion.dev): каждый кадр — React-компонент, анимация — от номера
кадра. Цвета считаются тем же алгоритмом Material You, что и на телефоне.

```bash
npm run studio            # редактор с превью
npm run render:variants   # все варианты, en + ru → out/variants/
node scripts/stills.mjs LongRu /tmp/stills 120 186 320   # отдельные кадры для проверки
```

## Ролики

| Composition | Файл | Идея |
|---|---|---|
| `Promo`, `PromoWide` | `Promo.tsx`, `DayScene.tsx` | Общий ролик: лента дня, темы, виджеты, финал |
| `Swipe` | `Swipe.tsx` | Свайп — и завтра: карточки отстают на пружинках |
| `Chips` | `Chips.tsx` | Три события подряд чипами, каждое быстрее |
| `Long` | `Long.tsx` | Месяц раздувается пузырём и лопается → долгие события на своей странице |
| `Colors` | `Colors.tsx` | Каждое открытие — новые обои и новые цвета, светлые и тёмные |

У каждого есть пара `…Ru`.

## Скриншоты для Google Play

`Store.tsx`: настоящий экран с эмулятора в телефоне, крупная подпись, фигура темы за ним, одна
мысль на кадр. Кадры `Store-<кадр>-<язык>` (1080×1920) и обложка `Store-feature-<язык>` (1024×500).

```bash
node scripts/store.mjs out/store          # все кадры → out/store/{en,ru,de,es,fr,hi}/
```

Экраны лежат в `public/store/<язык>_<экран>.png` (1080×2400). Снимались на отдельном чистом
эмуляторе (Android 16, без аккаунта, иначе в кадр попадёт личный календарь):

- данные — `python3 scripts/demo_calendar.py <язык>|clear`: локальный календарь, события вокруг
  «сейчас» (время берётся с эмулятора), поездка «день 3 из 7», отпуск через 12 дней;
- часы — `settings put global auto_time 0` и `cmd alarm set-time <мс>` на ~15:15, иначе утром
  события уезжают в ночь; 24-часовой формат — `settings put system time_12_24 24` (для hi — 12);
- виджет обратного отсчёта держит id события: после перезаливки данных тапнуть по нему и снова
  выбрать «🌴»;
- цвет обоев без обоев: `settings put secure theme_customization_overlay_packages` с
  `system_palette` (#FFC94D, стиль CONTENT — как `JUICY`), тёмная — `cmd uimode night yes`;
  активность пересоздаётся сама, перезапускать приложение не нужно (холодный старт долгий);
- статус-бар — демо-режим SystemUI (`com.android.systemui.demo`), часы — текущее время;
- язык — `cmd locale set-app-locales com.lpavs.caliinda --locales ru-RU`; adb-тапы — через
  `input touchscreen`, а рукописный ввод стилусом выключить, иначе вылезает его подсказка. Общие детали — `kit.tsx` (карточка, шапка, палец, подписи, физика
«веса»), финал — `End.tsx`, схемы — `schemes.ts`.

## Принципы

То, ради чего приложение делалось и что ролик должен передать, — **ощущение**, а не список функций.

- **Живость важнее показа функций.** Нужна физическая метафора и драматургия: месяц надувается
  пузырём и лопается — «БАХ!» — а потом тишина и порядок. Просто «вот экран, вот кнопка» — скучно.
- **Карточки — реальные предметы.** У них есть вес и пружина: при листании отстают и догоняют
  с перелётом (SpringyScroll), падают и приземляются с отскоком, при посадке сплющиваются, соседи
  вздрагивают. Ничего не появляется просто так — всё прилетает, пружинит, толкает соседей.
- **Текущее событие поднимается к зрителю.** Как в приложении: третичный цвет, узкий наклонный
  шрифт, одна плотная тень (4/5/2 dp, 50 %) — карточка висит над остальными. Подъём 12 dp в
  приложении у раскрытой нажатием карточки, не у текущей; большая размытая тень темнит зазор и
  выглядит как наезд на соседа. В ролике
  она ещё чуть крупнее, а камера подъезжает к ней, чтобы был виден ползущий червячок прогресса.
  Взгляд должен сразу цепляться за «сейчас». Растёт на месте, без сдвига вверх: зазор между
  карточками 6 dp, иначе наезжает на соседа выше.
- **«Сейчас» в каждом ролике своё.** Не одно и то же событие везде. Можно с подмигиванием: в
  «Чипах» текущее — «📲 Установить Caliinda».
- **Цвета — сочные.** Бледный Tonal Spot выглядит блекло. Для светлых сцен — насыщенный цвет как
  есть (`JUICY`: Content из `#FFC94D` — сочный подсолнечный, но не кислотный: неоновый `#FFD600`
  уже «ядовит») или тёплый
  «Яркий» (`WARM`). Динамические цвета — главная красота, их стоит показывать.
- **Светлая тема — по умолчанию.** Порядок и чистота — это белый. Тёмную показываем как
  разнообразие (ролик о цветах, смена тем), но не как основную.
- **Меньше переходов, но со смыслом.** Не нарезка ракурсов ради нарезки, а переход, который сам
  что-то показывает: цвет приходит фронтом (от кнопки настроек, из фоновой фигуры темы), и каждая
  карточка, до которой он дошёл, пружинисто откликается.
- **Верить физике.** Вес карточек — это пружина и отклик, а не падение с высоты: тонкая карточка с
  огромной тенью не выглядит тяжёлой.
- **Чётко, без зерна.** Никакой 3D-камеры с большим увеличением: браузер растеризует слой в
  обычном размере и растягивает. Увеличение — не больше ~1,15, фигуры-маски — векторные.
- **Пружины, а не плавные кривые.** Почти всё — `spring` с лёгким перелётом. Камера — резкий
  разгон и мягкая посадка.
- **Слова.** Не «проекты», а «всё, что дольше дня» / "anything longer than a day". Подписи
  короткие, слова выпрыгивают по одному.
- **Честность.** Экраны повторяют приложение: размеры в dp (`DP = 1080 / 411`), высоты карточек
  по той же сигмоиде, подписи чипов из `strings.xml`. Чего в приложении нет (например, подъёма у
  текущих долгих событий), в ролике тоже нет.
